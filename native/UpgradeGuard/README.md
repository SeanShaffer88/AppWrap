# Selected-destination upgrade guard

Original AppWrap MIT source; the repository LICENSE applies. Windows x86 helper with no console window, compiled with MSVC19.44.35207/Windows SDK10.0.26100.0. `Build.cmd` uses the installed x64-to-x86 compiler, static Microsoft CRT (`/MT`), `/GS`, `/W4 /WX`, ASLR and DEP. Build-time Visual Studio is required only for rebuilding this helper. The helper is embedded in AppWrap.Build and extracted into the generated installer's private plugin directory. It has no persistent state, network, service or background work.

Interface: `AppWrap.UpgradeGuard.exe <absolute-selected-root> <launcher-filename> <source-relative-payload-exe>`. The latter target is under `App/Payload`. Only exact full-image-path matching process handles qualify; no process-name termination. All matching payload windows receive bounded WM_CLOSE, then the root shims finish. Ten-second overall close budget, bounded enumeration, re-enumeration before success. Target aliases, links, UNC/device paths and ambiguous paths fail closed. Only the main executable and AppWrap launcher are covered; arbitrary children/services and self-restarting applications are outside the contract.

Exit codes:0 no targets remain;2 invalid/unknown path or identity;3 denied identity inspection;4 close timeout/refusal;5 Windows operation/resource failure. Missing targets are allowed for fresh installation. No elevation or force termination. No output files or telemetry. Imported source NSH/NSI is rejected by AppWrap. The generated trusted hook is inseparable from `CloseEXE=NONE`; normal payload replacement begins only after guard success.

Microsoft static CRT components remain subject to the installed Visual Studio license/redistribution terms; these components are not relicensed as MIT. This binary imports system KERNEL32/USER32/SHELL32 only, not an external CRT DLL. Rebuilding can change bytes; record the resulting compiler evidence and hash. Native execution qualification is separate from static PE inspection.
