## Validation and operation planning

1. **Path grammar:** separate package-relative App/Data/DefaultData paths, tokenized host paths and runtime-selected install root. Reject traversal, ADS/device paths, empty expansion, broad root targets, reparse aliases, reserved components and overlapping ancestor/descendant rules. Do not expand the developer's APPDATA into the package. Tokens come from versioned exact capability dictionary; custom environment references allowed only in ordered defined values, no cycles/forward reference/unknown expansion. Every tokenized path has a static allowed-base plus nonempty app-specific suffix. Expert custom absolute host roots require explicit exact scope and evidence; they are not a broad default permission.
2. **Data actions:** prefer app-native command-line/environment redirect first, then PAL FilesMove/DirectoriesMove with backup/restore. Create required Data parents via staged DefaultData, excluding Data/settings from directory movement. Initial data copied as defaults only; don't snapshot developer personal settings automatically. Wildcards bounded to reviewed suffixes, not whole USERPROFILE/APPDATA/Documents/TEMP/drives. Source/payload/assets remain immutable during build.
3. **Registry:** parse hive/key/value/type separately; HKCU app-specific default, HKCR normalized per PAL; HKLM/elevation explicit expert declaration, never automatic creator elevation. Reject whole hive, Software, Classes, startup/security/system-service roots and unrelated app scopes. RegistryValueWrite requires a matching encompassing backup/restore key or backup-delete value rule. Preserve-vs-discard is explicit. Show view field with Engine default supported;32/64/Both are explicit unsupported until exact plugin/adapter proof—no made-up keys. Block destructive cleanup overlapping restored keys or arbitrary local data. Validate value binary/numeric representation against actual plugin; ambiguous multi-string/resource/link types remain visible but unbuildable until exact encoding fixtures pass.
4. **Lifecycle:** WaitForProgram=true whenever any move/registry/temp restoration depends on exit. WaitForOtherInstances=true for restarting/multiprocess applications. Warn/reject unsafe combinations of shared host state with multi-instance/local coexistence. Supported single-instance policy must reflect PAL mutex AppID/baseName scope and basename checks, not a fake per-folder lock. No generic root-shim exit-code promise carries over to PAL without test/adapter.
5. **Cleanup risk:** RegistryCleanupForce and DirectoriesCleanupForce are fully discoverable expert controls with explicit destructive-action labels and no default entries. Require exact owned scratch scope, justification and confirmation within product before enabling; use protect/discard alternatives for preexisting user state. No hidden force deletion to satisfy universal claims. The user's request to support configuration authorizes building this UI; a build does not itself run cleanup.
6. **Install rules:** validate10-item upstream limits, preserve/remove precedence/overlap, exact files vs directories and Data impact. Preserve Data by default; no obsolete RemoveDataDirectory setting or broad wipe UI. Online download/copy-local/legacy/plugin modes are separately typed and expose all documented keys. These can execute before existing PreInstall guard; do not enable combinations until reviewed earlier-safe guard order exists. Show precise compatibility diagnostic instead of silently bypassing guard or dropping settings.
7. **Build source:** no scripts execute while importing/editing/previewing. Ordinary Launcher.ini values remain data, not shell/preprocessor. Metadata/compile defines need separate NSIS literal encoding; command invocation always separate argv and bounded. Trusted .nsh/custom code is executable at compile/runtime; trust binds exact path+hash+purpose+asset closure, invalidates after edit/import/drift, and is off by default. A schema `trusted:true` string imported from a file is not user trust. Preserve and show exact custom source; never weaken validation automatically to compile it.

## PAL runtime, recovery and upgrade integration

Use exact official source adapter rather than replacing PAL semantics with bespoke file-copy code. Stage `App/AppInfo/Launcher/<AppID>.ini`, `App/DefaultData`, and source/license/provenance in owned package. Compile with PAL's pinned NSIS2.46.5-Unicode, correct PAL version metadata and conditional XML/UAC flags. Preserve dynamic .reg/settings and source configuration. Require actual root launcher bytes and compile logs; never fall back silently to the basic shim when PAL configuration fails.

Existing preflight upgrade helper must accept a bounded generated manifest/list of **all** configured package executables (base/x64/when-parameter variants plus any exact helper paths configured), validated at build and runtime under selected INSTDIR. Close only exact owned payload images gracefully, wait all relevant payload handles, then **wait for PAL root to exit naturally after post-cleanup**. Never send WM_CLOSE/terminate PAL root while cleanup may be active or unknown named children remain. `WaitForEXEN` names cannot safely authorize closing arbitrary same-name processes; wait for PAL root boundedly or require exact path mapping. Timeout aborts upgrade before package/Data mutation, retaining launcher state. Process/file/registry scope conflicts remain a build/profile diagnostic.

### P4 early internal mutation gate

Full installer options cannot reuse the current public PreInstall hook as if it ran before Downloads/OptionalCleanup/Legacy. Controller approved the following distinct internal seam for that phase: in a clearly versioned AppWrap-derived copy of the pinned installer NSI, insert an internal `AppWrapPreMutation` invocation at the main installation Section's first mutation boundary, immediately **before the existing `SetOutPath $INSTDIR` aroundline1210**, after destination selection is final and before any download/copy/optional/legacy logic. Keep public `CustomCodePreInstall` execution at its original1683 location; never silently change the ordering of user custom hooks. Hook implementation must be present for profile builds and fail compilation if missing, not a nonfatal optional safety feature. No other installer semantics change.

The internal guard embeds/extracts the first-party native helper only into private plugin temp and supplies a validated runtime mutation plan. It must include primary selected INSTDIR and **every actual derived legacy destination root** that the enabled rules can create/copy/rename/remove, not merely the default AppID root. Derive legacy sibling leaf names from allowlisted suffix/custom-AppID metadata and runtime source-version/host conditions; canonicalize under the selected parent, reject traversal/reparse/overlap/arbitrary roots. Process targets cover all declared executable variants in every mutated root. A copied local installation used as a read-only source is not permission to close that foreign app. If the mutation plan cannot determine all target roots/executable lifetimes safely, block that specific combination with an actionable capability error before package publication; do not call the whole feature implemented while it remains blocked.

Only after exact owned payloads close and every affected PAL root exits naturally may any package mutation proceed. Installer abort/cancel on failed guard leaves existing application/Data trees untouched; plugin-temp preparation is documented separately. User-supplied optional/legacy/custom hooks cannot precede or replace this internal gate. Arbitrary trusted source can declare additional affected roots only through an explicitly reviewed extension contract; unknown side effects mean unqualified, not silently contained. Tests must prove active existing legacy destinations remain unchanged when any guard fails, and selected-destination changes affect only the new actual plan.

This seam modifies the **generated installer source**, unlike the earlier wizard-only patch. Preserve prominent modified notices, exact corresponding source/patch/build recipe and GPL obligations. Do not claim upstream unmodified-installer freeware exception still applies to the modified generated installer. Public nonfree/commercial payload distribution remains a rights/licensing gate; an explicit user feature request authorizes implementation work, not third-party permissions. Current packaging-only path may retain its already-qualified unmodified installer adapter until the new full-feature adapter passes separate gates.

Stock PAL host backups include file/directory `.BackupBy<AppID>` artifacts and HKCU/Software/PortableApps.com/Keys/Values subtrees; runtime INIs are mirrored on Data and plugin temp. Show these planned writes in Profile review/evidence (not backend-centric default question). Detect stale recovery markers/backup collisions before a test or the first guarded profile run; do not overwrite/delete existing unknown backups. Source contains partial continuation on failed moves/registry restore: actual failure fixtures decide whether a minimal reviewed PAL preflight/error patch is required. Any profile unable to meet fail-closed host-data preservation remains not qualified; don't claim stock engine guarantees rollback under every failure.

Normal payload exit, including nonzero/crash of child while PAL remains alive, should run post-cleanup; prove it. Killing PAL, power loss, drive removal and concurrent mutation are separate recovery cases. Record recovery instructions and owned artifact identity; do not promise unconditional cleanup after launcher loss. Runtime tests operate only unique owned fixtures/scopes, not arbitrary real app/user data. No broad host scan or hidden process monitor.
